# Verifier `score()` contract (protocol App. A.2, II.4, II.7.1)

This is the interface V₁ / V₂ implement and that `rafr.verifiers.stub` mirrors
exactly. Anything that satisfies this spec can replace the stub without touching any other
module.

## Signature

```python
class Verifier(Protocol):
    verifier_id: str          # stable identifier, e.g. "v1-deberta-toxic-2026-09"
    model_version: str        # HF repo + commit hash, or equivalent; goes into every Score row
    batch_limit: int          # maximum number of texts per score() call

    def score(self, texts: list[str]) -> list[float]: ...
```

`rafr.core.interfaces.Verifier` is the runtime `Protocol`; `rafr.contracts.schemas.Score`
is the on-disk row.

## Semantics

| Item | Rule | Source |
|---|---|---|
| Range | every value in **[0, 1]** (inclusive) | decision 5(a), 2026-09-16 |
| Direction | **higher = more toxic** | II.7.1 (score semantics) |
| Scale comparability | V₁ and V₂ scales are **not** comparable; nothing downstream subtracts one from the other | II.7.1, C.4 |
| Length | `len(score(texts)) == len(texts)`, same order | — |
| Determinism | same `(model_version, text)` → same score, bit-for-bit, across calls and processes | II.10 (reproducibility); verifier_card must state the guarantee |
| Purity | reads only the text; no labels, no arm, no other verifier's output, no E | II.5.2, II.9.1 |
| Empty input | `score([]) == []` | — |
| Batching | caller never sends more than `batch_limit` texts per call; `rafr.verifiers.batch_score` chunks | A.2 |
| Failures | raise; never return NaN/None. A NaN/None is a contract violation | — |

## The formal implementation (2026-09-24)

`rafr.verifiers.factory.make_verifier(config_id)` is the only `score()` a formal step uses
(`configs/models.yaml: verifiers.factory`). It returns the step 2 probe's own scorer for the
probe configuration `config_id`, with every parameter checked against the probe's records, so
the probe's tables and the step-6 table are on one scale. The registry's guard-LM wrappers are
not a formal implementation (double BOS; decisions.md D-2026-09-24b point 4).

## Threshold τᵢ

`score()` does **not** apply a threshold. τᵢ is fitted on D_fit (II.4.1, v0.9: F1-max,
plateau midpoint) by `rafr.validity.tau` and frozen in `frozen/tau.json`. The judgment
`yᵢ = 1[sᵢ ≥ τᵢ]` and the margin `mᵢ = sᵢ − τᵢ` are computed by `rafr.formatter.fields`
from `s_obs`, never inside the verifier.

## Scores table on disk (App. A.2)

`data/scores/<verifier_id>.jsonl`, one `Score` row per line:

```json
{"state_id": "...", "verifier_id": "...", "model_version": "...", "prompt_hash": "...", "score": 0.87, "sub_scores": null, "timestamp": "..."}
```

`prompt_hash` (guard LMs; null for an encoder) and `sub_scores` (per-policy scores when `score`
aggregates several calls, e.g. ShieldGemma native = max over two policies) were added for the
step 2 probe (2026-09-24): the probe table and the step-6 table share one schema, so the
configuration finally chosen can be reused without rescoring. Both are optional; older rows
without them still load.

`rafr.verifiers.batch_score` reads `to_score.jsonl` (`state_id`, `text`) and appends rows in
this format to `data/scores/<verifier_id>.jsonl`. It is resumable: states already in the
table are skipped.

## verifier_card.md (App. A.2)

Generated by `python -m rafr.verifiers.cards.generate` from the manifest that
`env/download_models.sh` writes, so the revision and the hashes are never typed in by hand.
Must state: model identity, HF repo + commit hash + weight sha256, τᵢ determination pointer
(`frozen/tau.json`), score direction and range (must say `[0,1]`, higher = more toxic),
`batch_limit`, and the determinism guarantee (dtype, deterministic kernels, fixed padded
shapes, fixed tokenizer revision). It also states the truncation policy, which logit or
class the score is read from, and how it is normalised.

## Stub

`rafr.verifiers.stub.StubVerifier` is a deterministic hash-based scorer with the same
signature and semantics, used **only** by tests and `pipelines/step03_dry_run.py`. Its
`verifier_id` starts with `stub-`; formal steps refuse a `stub-` verifier.
